# 全网调研编排 (Web Research Fanout)

核心原则：**覆盖面来自独立源，不来自数量**。派几个 = lane 数（子问题 × 源类），不是拍一个固定数字。
同题克隆的多个 researcher 会从同一批搜索结果里捡同一批页面 → 相关性误差互相强化，产出"自信的错误"。

## 0. 先判断要不要 fan-out

- 单点事实（一个数字/一个链接）→ 不派或只派 1 个，主会话直接搜索/抓取。
- 需要"一张地图"（覆盖面、多源互证、冲突多的领域）→ fan-out。
- 读手头文档/PDF → 用 `dual-read`，不用本 skill。

## 1. 火力档位（按 lane 数选，不按心情）

| 档 | 规模 | 何时用 |
|---|---|---|
| 快查 | 2-3 | 一个主张需 2-3 个独立来源互证 |
| 标准（默认） | 5-8 | 一次完整调研，按源类切 5-8 条 lane |
| 重型 | 10-20 | 能列出 ≥10 个**真正独立**的源/子题（多语言、多平台、多品类）才配；凑不出独立源就不许开 |

lane 划分示例（按源类切）：官方公告/文档 ｜ 代码仓库与 issue ｜ 基准/评测站 ｜ 社区实测（Reddit/HN/V2EX）｜ 中文来源 ｜ 价格页/条款 ｜ 监管/一手文件。
每条 lane 的 researcher 必须拿到**不同的种子**（关键词措辞/语言/站点限定至少换一个），否则就是克隆。

> **质量公式**：质量 = 独立源 × 对抗验证 × 仲裁；数量只是放大器。加一条 lane 之前先问：它和已有 lane 在哪个维度独立——源类、语言、立场、模型家族？一个都不占，就是克隆，只会放大相关误差。
> **模型分工**：lane 是标准化作业——中档模型够用（实测：格式契约的依从性足够，翻车多在通道不在脑子）；真正吃模型判断力的是三处：主会话拆题/合并、对抗 lane、仲裁。**异族 ≠ 更贵**：跨家族的目的是盲区不相关，任一不同家族的中档模型即可，不必买贵的。

## 2. 派发（一条消息并行，分批投放）

- 一条消息里同时发多个 Agent（subagent_type: `researcher`），不要串行。
- **单批 ≤6**；重型档分批投放（避免网关限流）。
- **通道先验证、再写进任务**：主会话先验证一条可用通道，把**完整命令**写进任务模板——子代理没有 Skill 工具、加载不了别的说明书，命令必须给全。常见通道：搜索 API（Exa 等，经 mcporter/MCP 或 curl 调用）｜ 搜索引擎结果页抓取（Bing/Brave）｜ r.jina.ai 读页 ｜ `gh` ｜ `yt-dlp`；社交平台类通道先验证可用再写进模板。
- 每个任务必须**自包含**（子代理看不到主会话）。派单分两部分——必须分开维护：
  - **不变量 brief**——lane 派出那一刻即冻结：问题、范围、种子词、下面的输出契约。之后**永不改写**；改 brief = 作废这条 lane 的全部证据。缺口靠**加新 lane**解决（见两轮制），绝不重发改写过的 brief。
  - **参数块**——可调旋钮（预算、模型、档位），记进派发留账，不嵌进 brief：`node <pack-root>/tools/ledger/dispatch-ledger.mjs append --params-file <params.md> ...`。每条结论都可追溯到产生它的那套参数——旋钮一改，立刻知道哪些结论被作废。

  模板（不变量部分）：

```
调研任务（lane: <名称>）。
目标：<一句话问题>。范围：<源类/站点/语言>。种子词语：<3-5 个关键词或站点限定>。
工具：优先 Bash 跑搜索命令，例如 mcporter call 'exa.web_search_exa(query: "...", numResults: 8)'（按你的环境替换）；
读页面用 node <pack-root>/skills/web-research-fanout/scripts/fetch-hard.mjs <url>（链式降级：真 UA 直抓→HTML转文本→r.jina 兜底）或 WebFetch；
搜索引擎页兜底（上面两条都不通时才用）：www.bing.com/search?q= / search.brave.com/search?q=；DuckDuckGo 全系被验证码拦，别用；
遇 403/封禁：升一级（见第 6 节），仍被拦就停止并在报告里标"被拦：<站点> <状态码>"，不许硬刚。
输出契约（严格遵守——全包统一五段结构，见 REPORT-CONTRACT.md）：
## 结论 —— ≤3 行
## 发现 —— 1) claims 表，每行：断言 | 来源URL | 日期 | 一手/二手 | 有无反证   2) "查不到 / 互相矛盾" 清单
## 已验证 —— 追到一手来源的行（每行带 URL）
## 未覆盖 —— 被挡住的："被拦：<站点> <状态码>"
## 已跳过 —— 主动降级的来源（附原因）
只回以上内容，不贴原文。
```

  参数块（走派发留账记录，不嵌进 brief）：
  `预算：≤8 次搜索 + ≤10 次读页；一个断言拿到 2 个独立来源即停。` · `模型：<按派发时填>` · `档位：<快查|标准|重型>`

### 大题（重型档 / 结论会被拿去决策）走两轮，不要一把梭

1. **侦察轮（主会话，5-10 分钟）**：先自己快搜 3-6 次，摸清关键实体、官方源在哪、各家说法差异点 → 用它划 lane、定种子词。（高成本任务可在此加一道"计划门"：把拆题方案给用户过目再开工。）
2. **采集轮**：按 lane 并行派 researcher（单批 ≤6）。
3. **缺口轮**：只针对三样东西再派 1-2 个**新增** lane（全新 task-id）——"查不到清单"、冲突项、载重断言的反证。**第一轮的 brief 保持冻结**：绝不重发改写过的 brief，那等于把第一轮已经定下的结论全部重新开封重付。缺口是新 lane，不是打补丁的旧 lane。

一把梭的代价：lane 拿着模糊种子自己摸，预算全烧在找关键词上。

## 3. 主会话做机械合并（不是通读全部报告）

- **合并前先过机械门**：`node <pack-root>/tools/gates/claims-lint.mjs <lane-output.md>` 必须 exit 0。它机械拦截：缺公开 URL/日期/一手二手标记/反证列的行、非公开 URL、以及标了冲突却没有对应仲裁小节的报告。哪条 lane 没过门就退回哪条 lane，不许绕过它手工合并。
- 按断言去重：同一断言多个来源 → 合并成一行，记来源数。
- 机械标记两类问题：①关键断言只有单一来源 ②同一断言结论互相冲突 → 进「冲突清单」。
- 主会话只保留合并后的表 + 冲突清单；不要把所有原文塞进上下文。
- 每条 lane 的结局都记进派发留账（`tools/ledger/dispatch-ledger.mjs`）——没产出可用结果的 lane 是 `failed-protocol` 或 `failed-definition`，不是耸耸肩（故障三分类见附录）。

## 4. 核验与仲裁（默认最高配：一手回源 + 对抗 + 跨家族）

对**每一条载重断言**（结论赖以成立的断言）默认做三件事——标准档起全做，快查档至少做①：

1. **一手回源**：断言必须能追到一手来源（官方页面/官方仓库/原始文件）；只有二手来源的，标注"待一手复核"，不算定论。
2. **对抗 lane**：派 1 个专门"找反证"的 researcher——搜 "X 是错的 / 不推荐 / 翻车 / 骗局"，找一手文件打脸；找不到反证本身就是产出（报告里写一行"未发现反证"）。
3. **跨家族仲裁**：核对员/仲裁员用**与 lane 不同模型家族**的模型——目的是盲区不相关，不是买更聪明。只喂冲突清单 + 对抗结果，要求**逐字引用原文关键句**作依据。

- 仲裁输出用 一致/增量/矛盾 三分类（与 dual-read 同一套）+ 每条矛盾：各方来源、日期、一手性、采信建议或标"存疑"。
- **禁止多数票=对**：独立来源数 > 投票数；一手 > 二手；新 > 旧。

## 5. 产出格式

lane 报告和最终合并交付物都遵循全包统一的五段报告契约（`REPORT-CONTRACT.md`）：**结论 / 发现 / 已验证 / 未覆盖 / 已跳过**。本 skill 的对应关系：

- **发现** = 合并后的结论表（断言 | 来源 | 日期 | 置信——这是对各 lane 的*合并视图*；各 lane 交上来的 claims 表仍保留 `claims-lint.mjs` 检查的完整五列契约）+ 存疑清单（附冲突双方与各自来源）。
- **已验证** = 追到一手来源的载重断言（每条带 URL）。
- **未覆盖** = `被拦：<站点> <状态码>` 项——试过，被挡。
- **已跳过** = 参数块里主动降级的来源——决定不抓，附原因。
- 存疑项必须显式标出，不许悄悄丢掉。机械化把关：`node <pack-root>/tools/gates/report-lint.mjs <report.md>`。

**交付前自检（逐条过，过不了不许交）**：

- 什么证据能推翻这个结论？找反证 lane 的产出行在哪？
- 载重断言是否都追到一手来源？只挂二手的有没有标"待一手复核"？
- 来源时效：关键数字类 ≤7 天、背景类 ≤30 天；超龄的标"陈旧"并说明。
- "查不到清单"是否如实保留？有没有被悄悄删掉？

## 6. 反爬升级阶梯（抓不动时按顺序升，一次不开倒车）

任何通道遇 403/封禁：**升一级，不要重试同一级**。重试在"真实拦截"面前没有意义——实测：对 Reddit 的 curl+浏览器 UA、无头浏览器、r.jina、WebFetch 全部 403 = **出口 IP 级封禁**，再强的爬虫也进不去。

| 级 | 通道 | 适用 | 做法 |
|---|---|---|---|
| L0 | 官方 API / 公开 JSON | 有 API 的站（HN Algolia、GitHub、Reddit OAuth、各类 `.json` 端点） | 直接用。永不被拦，永远第一优先 |
| L1 | **索引层**（绕开实时请求） | 实时被拦、但被搜索引擎索引的站（Reddit 实测有效） | 搜索 API 的 `site:` 语法（如 `exa.web_search_exa(query: "site:reddit.com 关键词")`）→ 返回帖子标题/作者/日期/正文要点，不碰原站 |
| L2 | 直抓 / 链式降级 | 普通静态页、轻反爬 | `fetch-hard` 脚本（真 UA 直抓 → HTML 转文本 → r.jina 兜底）或 WebFetch |
| L3 | 换出口 IP | 按 IP 封的站（机房 IP 被拉黑） | **主会话操作**：换代理出口节点后重试（最便宜的 IP 级解法） |
| L4 | 真浏览器 | JS 渲染重、登录态资料 | **仅主会话**：宿主浏览器工具或操作用户真实浏览器（cookie 全在）→ 抓到的内容**落盘成文本**给子代理读 |

- **researcher 只允许用 L0-L2**；被拦至多升一级，仍被拦 → 立即停止，在 lane 报告里标 `被拦：<站点> <状态码>` 上交主会话，**不许烧预算硬刚**。
- **通道按站分野，实测**：`fetch-hard` 对普通站直抓即通；对难站（Reddit、知乎）直抓与 r.jina **同时 403**——jina 只在普通站有效，救不了难站。难站的解药是 **L1 索引层**（`site:reddit.com` / `site:zhuanlan.zhihu.com` 均能拿到正文要点），别在 L2 上耗。
- L1 拿到的是**索引快照**（可能不是最新）：关键断言要用 L0/L2 复核，或在"日期"列标注为索引时间。
- 子代理通常没有浏览器工具——硬站点走"主会话抓 → 落盘 → 子代理读"。

## 附：预算与已知坑（实测修订）

- **真实成本（4 lane 低配实测；标准档为 5–8 lane）**：单 lane 8.4万–26.2万 token（看抓页量）；4 lane 合计 ≈ 56 万 token，墙钟 ≈ 5 分钟（并行）+ 仲裁 1 分钟。重型档 10-20 lane 预估 150万–400万 token/轮——开重型档前先确认额度够。
- **极致模式成本**（对抗 lane + 跨家族仲裁 + 两轮制）：约标准档的 1.5–2.5 倍，墙钟 15–25 分钟；结论会被拿去决策时值得。
- **lane 生产力排序（实测）**：官方文档/一手页面 ＞ GitHub 仓库 README/issue ＞ 社区讨论。英/中文社区 lane 成本最高、产出最差。
- **Reddit 类难站可能整体被出口 IP 封**（curl+UA、无头浏览器、r.jina、WebFetch 全被拦）→ 用 L1 索引层（实测可读到帖子正文要点）；HN 用 Algolia API（hn.algolia.com/api/v1/search?query=...，永不被拦）；都取不到就如实标"未获取"，不要硬凑。
- **Bing 搜索页对中文关键词会返日文垃圾结果**（分词失效）→ 中文 lane 用 Brave 或英文种子词。
- **各家"免费额度"数字常年藏在 403 的定价页后面** → 需要 Bash+curl 或登录态通道才能拿到；拿不到就标"存疑：未取到一手来源"。
- **失败处理 = 先归因，再行动。**「重派一次」不是一条规则；三类失败的正确动作互相相反：
  - **`failed-transport`**（超时、10 分钟无输出被 inactive 杀、Turn execution failed、供应商 4xx/5xx）：重试归宿主/供应商层管。不要烧协议重试——等待后经留账再查。记 `mark --status failed-transport`。
  - **`failed-protocol`**（lane 产出不成形、没有 claims 表、不遵守契约）：缩小范围**重派一次**；第二次还是协议失败，说明问题在 brief 不在通道 → 按 `failed-definition` 处理。
  - **`failed-definition`**（lane 的问题本身派错了、和别的 lane 重复、按现规格根本不可达）：**绝不原样重派。**作废该 lane，作废所有依赖它的结论，用修正后的不变量 brief 开新 lane。
  - 每个结局都记 `tools/ledger/dispatch-ledger.mjs mark`——不落账的失败等于静默失败。lane 抓取统一走 fetch-hard（自带超时），避免长挂起。
- 实测通道排序：搜索 API（mcporter/Exa）＞ fetch-hard（L2 直抓/链式降级）＞ Brave/Bing 搜索页抓取（质量波动）＞ 主会话浏览器（L4）。
- 子代理配置在多数宿主是**会话启动快照**：改了 researcher 的 tools/system prompt 要新开会话才生效。
- 本协议设计时参考了同期开源项目（red-team/claims 账本、审查隔离等思路），致谢见仓库 README 的 Related work。
